## Current Status

Akari 当前处于 **V2 MVP 主闭环已实现、等待完整手动验收与后续打磨** 的状态。

V1 的对话式规划、Workspace、任务管理、会话持久化和 Agent 工具调用已冻结为稳定基础；V2 已在此基础上补齐任务反馈、复盘素材、计划版本、手动规划、日视图切换和详细 Markdown 周复盘。

## Product State

当前可演示的核心路径：

1. 用户可以通过聊天诊断生成本周计划，也可以不经过 Agent，直接手动创建目标与空周计划。
2. 用户可以在「我的规划」里编辑目标标题/描述，切换本周任意一天，手动添加、编辑、完成和拖拽任务。
3. 用户完成今日任务时可记录实际用时、难度、专注状态和一句简短感想；周视图保持快速完成。
4. 用户可以在「复盘素材」里粘贴错题原件/批注，生成候选素材并确认入库。
5. 用户可以在聊天区上传或引用粉笔 PDF / workspace 文件；Agent 先分拣是否为复盘素材，再询问是否计入复盘和是否关联今日任务。
6. 用户可以生成本周详细 Markdown 复盘，并用浮窗查看；复盘重点是整理数据和自查问题，不替用户判断真实思路。
7. 用户可以打开计划 Markdown、查看计划版本、恢复历史计划、归档 active 计划、删除 archived 历史计划。
8. Chat 支持 Markdown/GFM 表格渲染；Agent 可在合适时输出选择题指令并渲染为按钮。

## Architecture Snapshot

- Frontend: React 19 + Vite 7 + Electron shell.
- Backend: Node 24 + TypeScript 5.9 + Express + `ws`.
- Database: SQLite `.akari/akari.db` via better-sqlite3, `CREATE TABLE IF NOT EXISTS` additive schema.
- LLM: DeepSeek-compatible `/chat/completions`.
- Workspace: real filesystem rooted at `AKARI_WORKSPACE_PATH` / `~/Desktop/Akari-WorkSpace` with path sandbox.
- Chat persistence: JSONL sessions under `.akari/memory/sessions`.
- Settings: `.akari/config.json`, UI config overrides env defaults.

### Agent Layer

- `server/services/llm-client.ts`: DeepSeek HTTP/SSE client.
- `server/services/tool-registry.ts`: tool registration and execution boundary.
- `server/services/agent-loop.ts`: LLM → tool calls → tool results orchestration, max 8 rounds.
- `server/services/agent-context.ts`: static system prompt + current time.
- `server/services/intent.ts`: diagnostic routing and session-scoped planning state.

### Main Backend Areas

- `server/main.ts`: Express + WebSocket entry.
- `server/db.ts`: SQLite connection and table creation.
- `server/types.ts`: Zod schemas and DB row interfaces.
- `server/api/chat.ts`: legacy REST chat + `/api/chat/ws` stream route.
- `server/api/planner.ts`: plan, task, version, manual plan and goal metadata routes.
- `server/api/feedback.ts`: task feedback, artifacts, candidates, daily and weekly review routes.
- `server/api/workspace.ts`: workspace tree/file/upload/delete/rename/info routes.
- `server/services/planner-service.ts`: goal/tree/task/manual plan logic.
- `server/services/feedback-service.ts`: task feedback, review material candidate flow, weekly Markdown review.
- `server/services/plan-document-service.ts`: current-plan.md sync, history, version restore/archive/delete.
- `server/services/workspace-service.ts`: file sandbox, tree, read/write/upload/delete/rename, PDF/DOCX/text parsing.
- `server/services/chat-service.ts`: JSONL session read/write/list/delete and shortened preview titles.

### Main Frontend Areas

- `desktop/src/react/App.tsx`: top-level state orchestration, chat stream, plan/review/workspace handlers.
- `desktop/src/react/features/chat/ChatPanel.tsx`: Markdown/GFM assistant rendering and choice buttons.
- `desktop/src/react/features/chat/Sidebar.tsx`: shortened session list and delete/new/settings actions.
- `desktop/src/react/features/workbench/Workbench.tsx`: planning surface, review surface, workspace surface.
- `desktop/src/react/features/workspace/FileTree.tsx`: recursive workspace tree and context menu.
- `desktop/src/react/features/workspace/FilePreview.tsx`: text/Markdown preview with GFM table support.
- `desktop/src/react/features/settings/SettingsModal.tsx`: runtime settings UI.
- `desktop/src/react/services/api.ts`: REST client and WebSocket transport.
- `desktop/src/react/services/types.ts`: frontend transport/request types.
- `desktop/src/react/styles.css`: global layout, design system, workbench, chat, review modal and Markdown styles.

## Current Feature Details

### Planning

- Active goal can be generated by Agent or manually created via `POST /api/planner/manual`.
- Manual plan creates an active goal, default tracks/modules, current-week `weekly_plans`, an empty task list and a lightweight profile.
- Active goal title/description can be edited via `PATCH /api/planner/goal`.
- Day view no longer means only today: it can select any day in the current active week.
- Adding a task in day view uses the selected date, not the system date.
- Week view remains overview-oriented; clicking a day jumps back to day view for that date.

### Feedback and Review

- Task completion feedback is stored per task in `task_feedback` and syncs `daily_tasks.actual_minutes/status`.
- “错题归因” language has been shifted toward “复盘素材”: Akari organizes review materials; the user still does the real reasoning.
- Candidate review materials can be generated from pasted text, then confirmed/dismissed by the user.
- Uploaded PDF/workspace files are handled in chat: classify first, ask before recording, optionally link to a task, then write confirmed PDF diagnostics into review aggregation.
- Weekly review summary is now Markdown stored in `study_reviews.summary`, with sections for completion, material overview, PDF diagnostics, verbal-reasoning review table and next-week actions.
- The UI shows detailed weekly review in a modal using `react-markdown` + `remark-gfm`.

### Plan Documents and Versions

- Active plan syncs to `plans/current-plan.md` in the workspace.
- Historical snapshots are written under `plans/history/`.
- Version list supports current/history state, restore, archive and delete.
- Active plans are archived, not directly deleted; only archived history can be deleted.
- Archive/delete must not touch `.akari/` data or unrelated workspace files.

### Chat and Sessions

- Assistant messages render Markdown and GFM tables.
- Workspace Markdown preview also renders GFM tables.
- Agent can emit `[选项: ...]`; the frontend strips that line and renders choice buttons.
- Clicking a choice sends a normal user message: `我选择：...`.
- Session preview titles are shortened from the first user message and weak openings like “请帮我/帮我/我想” are stripped.

### Dev Server Behavior

- `npm run dev:web` starts API and Vite directly through local binaries instead of nested npm child processes.
- It checks ports `5173` and `8742` before starting.
- Vite uses `--strictPort`; if `5173` is occupied it fails instead of silently switching to `5174`.
- The script terminates child process groups on shutdown to reduce stale Vite/API listeners.

## Known Technical Follow-Ups

- Full manual P0 acceptance still needs to be rerun after the latest V2 polish.
- Lint currently has warnings but no errors; clean warnings only if they become noisy or block CI.
- V2 candidate extraction is deterministic/fallback-oriented; no OCR or vision model pipeline is implemented.
- Weekly review is Markdown stored in `summary`; there is no separate structured review schema yet.
- Markdown plan sync is DB → file; full Markdown import/back-write is still future work.
- No cross-week calendar navigation yet; day switching is scoped to the active weekly plan.
- No WebSocket `steer` / `resume_stream` implementation yet.
- Electron packaging is not done.
- Settings form remains long and can be sectioned later.
- Mood/thinking/card event parsing is not surfaced in the frontend.
- Sidebar width persistence is not implemented.

## Red Lines

- Do not delete `.akari/` files.
- Do not modify `.env` or `.akari/config.json` API keys.
- Do not perform DB schema migrations; current pattern is additive `CREATE TABLE IF NOT EXISTS`.
- Do not copy Hanako UI/Electron/backend code into Akari.
- Do not commit secrets.

## Electron Note

On Node 26, Electron postinstall can download the zip but fail to extract it completely via `extract-zip`. If `path.txt` or `Frameworks/` is missing, run:

```bash
bash scripts/fix-electron-macos.sh
```

The script matches the cached zip by the installed Electron version to avoid extracting an old cached version.

## Reference: Hanako Boundary

Hanako remains architecture reference only. Akari is a clean-room implementation with a different runtime and codebase. Do not copy Hana/Akari legacy UI, Electron shell, stores, theme files, assets, or backend code into this project. If any legacy migration is considered later, update originality documentation first.
